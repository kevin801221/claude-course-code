# 文件重構

依專案類型調整並重構專案文件結構：

1. **分析專案**：辨識類型（函式庫／API／網頁應用／CLI／微服務）、架構與使用者角色
2. **集中文件**：將技術文件移到 `docs/`，並建立正確的交叉參照
3. **根目錄 README.md**：精簡為入口頁面，包含總覽、快速上手、模組／元件摘要、授權條款、聯絡方式
4. **元件文件**：為模組／套件／服務層級新增 README 檔案，包含設定與測試說明
5. **依相關類別整理 `docs/`**：
   - 架構、API 參考、資料庫、設計、疑難排解、部署、參與貢獻（依專案需求調整）
6. **建立指南**（依適用情況選擇）：
   - 使用者指南：應用程式的終端使用者文件
   - API 文件：API 的端點、驗證方式、範例
   - 開發指南：設定、測試、貢獻流程
   - 部署指南：服務／應用程式的正式環境部署
7. **所有圖表使用 Mermaid**（架構圖、流程圖、結構圖）

保持文件簡潔、易於瀏覽，並貼合專案的實際情境。
