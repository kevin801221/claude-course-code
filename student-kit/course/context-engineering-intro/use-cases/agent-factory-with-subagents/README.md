# 🏭 使用 Claude Code 子代理人的 AI 代理人工廠 (AI Agent Factory)

這是一個強大且簡單的編排框架，利用 Claude Code 的子代理人 (Subagent) 能力，自主構建使用 Pydantic AI 的 AI 代理人。該系統透過專門子代理人的協調工作流，將基本的開發需求轉化為功能齊全、經過測試且具備說明的 AI 代理人。這可以在幾分鐘內完成傳統上需要數小時或數天開發的工作。

> **完整範例**：有關使用此框架構建的完整、可運行的 AI 代理人，請參閱 [混合搜尋 RAG 代理人 (Hybrid Search RAG Agent)](agents/rag_agent)，其中包含完整的設定說明和文件。

## 🚦 開始使用

1. **請求一個代理人**：在此目錄中開啟 Claude Code 並請求一個 AI 代理人 (請參閱下面的範例，您的提示可以很簡單)。
2. **回答釐清問題**：提供 2-3 個關於您需求的快速回答。
3. **見證奇蹟**：子代理人將平行工作，在 `agents/` 下的一個新資料夾中構建您的代理人。
4. **接收您的代理人**：包含測試、文件和設定說明的完整成果。

## 🎯 為什麼使用子代理人？

Claude Code 的子代理人備受推崇是有原因的。透過子代理人，我們可以獲得：

### **平行執行與擴展性**
- 同時執行多個專門的代理人，大幅縮短開發時間。
- 每個子代理人都在自己的上下文視窗中獨立運行。
- 編排複雜的工作流，而不會發生上下文污染或受到 Token 限制。

### **專門的系統提示詞**
- 每個子代理人都有一個針對其角色的、專注於特定任務的優化提示詞。
- 防止提示詞稀釋，並在各項任務中保持專業水準。
- 實現深厚的領域知識，且不損害通用能力。

### **模組化架構**
- 透過獨立的配置和工具實現清晰的關注點分離。
- 可重用的組件，可以在不同專案之間進行版本控制和共享。
- 易於擴展、修改或替換單個子代理人，而不影響其他代理人。

### AI 代理人工廠的工作流階段

1. **階段 0：釐清需求 (Clarification)** —— 主代理人提出針對性問題以了解需求。
2. **階段 1：需求文件 (Requirements Documentation)** —— 規劃者 (Planner) 子代理人建立全面的規格說明。
3. **階段 2：平行組件開發 (Parallel Component Development)** —— 三個專門的子代理人同時工作：
   - **提示工程師 (Prompt Engineer)**：設計優化的系統提示詞。
   - **工具整合員 (Tool Integrator)**：規劃工具實作和 API 整合。
   - **依賴管理員 (Dependency Manager)**：配置環境和依賴項。
4. **階段 3：實作 (Implementation)** —— 主代理人根據規格說明構建完整的代理人。
5. **階段 4：驗證 (Validation)** —— 驗證者 (Validator) 子代理人建立測試並驗證功能。
6. **階段 5：交付 (Delivery)** —— 文件編寫和最終封裝。

## 🤖 子代理人介紹

### **pydantic-ai-planner (規劃者)**
以 MVP 心態建立簡潔、專注的需求文件 (`INITIAL.md`)。分析使用者需求並為代理人開發產出清晰的規格。

### **pydantic-ai-prompt-engineer (提示工程師)**
設計精簡的系統提示詞 (100-300 字) 以定義代理人行為。專精於為 Pydantic AI 代理人建立清晰、有效的提示。

### **pydantic-ai-tool-integrator (工具整合員)**
規劃專注於 2-3 個基本功能的工具規格。定義工具參數、錯誤處理和整合模式。

### **pydantic-ai-dependency-manager (依賴管理員)**
配置最小化的依賴項和環境變數。設定模型提供者、資料庫連線和代理人初始化。

### **pydantic-ai-validator (驗證者)**
使用 `TestModel` 和 `FunctionModel` 建立全面的測試套件。驗證需求、測試功能並確保生產就緒。

## 🎨 CLAUDE.md —— 編排引擎

`CLAUDE.md` 檔案是系統的核心，包含：

- **工作流觸發器**：激活代理人工廠的模式。
- **階段定義**：每個開發階段的詳細指令。
- **子代理人提示**：每個子代理人的專門指令。
- **品質關卡**：每個階段的驗證標準。
- **整合規則**：各個組件如何協同工作。

關鍵特點：
- 從使用者請求中自動識別工作流。
- 為了最佳效能平行調用子代理人。
- 可選的 Archon 整合，用於專案管理。
- 全面的錯誤處理和恢復。

## 🔗 可選的 Archon 整合

當 [Archon](https://archon.diy) 透過 MCP 可用時，系統提供增強的專案管理：

- **自動建立專案**並帶有任務追蹤。
- 隨著每個階段的進展提供**狀態更新**。
- 實作期間使用 **RAG 驅動的研究**。
- 為迭代和改進保留**持久的專案歷史**。

Archon 整合是可選的 —— 系統在沒有它的情況下也能完美運行，使用本地的 `TodoWrite` 進行任務追蹤。

## 📚 Pydantic AI 整合

所有代理人均使用 [Pydantic AI](https://ai.pydantic.dev/) 構建，提供：

- **型別安全**：完整的型別提示和執行時驗證。
- **結構化輸出**：可靠、經過綱要驗證的回應。
- **依賴注入**：清晰的關注點分離。
- **測試支援**：`TestModel` 和 `FunctionModel` 用於全面測試。
- **多提供者**：支援 OpenAI, Anthropic, Gemini 等。

## 🛠️ 組件說明

### 規劃文件
每個代理人包含四個規劃文件：
- `INITIAL.md` —— 需求和規格說明。
- `prompts.md` —— 系統提示詞設計。
- `tools.md` —— 工具規格說明。
- `dependencies.md` —— 配置和依賴項。

### 實作檔案
- `agent.py` —— 主要代理人邏輯。
- `tools.py` —— 工具實作。
- `settings.py` —— 環境配置。
- `providers.py` —— LLM 提供者。
- `dependencies.py` —— 依賴注入。
- `cli.py` —— 命令列介面。

### 測試與驗證
- 使用 `pytest` 的全面測試套件。
- `TestModel` 用於開發測試。
- `FunctionModel` 用於行為驗證。
- 整合測試用於端到端驗證。

系統處理從需求分析到實作、測試和文件的所有其他事務。
