# 檢查點範例

在 Claude Code 中有效運用檢查點（Checkpoints）的實際範例。

備註：每次使用者提示都會自動建立檢查點，你不需要手動儲存。若要回溯，按兩次 `Esc`（`Esc+Esc`）或使用 `/rewind` 開啟檢查點瀏覽器。

## 範例 1：資料庫遷移

### 情境
你需要從 MySQL 遷移到 PostgreSQL，但想同時探索直接遷移與漸進式雙寫兩種做法。

### 工作流程

```
User: 我們直接從 MySQL 遷移到 PostgreSQL 吧
      [自動建立檢查點 A]

Claude: 我來實作直接遷移……
[變更資料庫驅動程式、更新查詢、修改資料庫 schema]

User: 執行測試
      [自動建立檢查點 B]

Claude: 執行測試中……
❌ 15 個測試失敗——連線池問題

User: 這個做法有問題，我們改試雙寫模式吧。
[使用者按下 Esc+Esc，選擇檢查點 A，選擇「還原程式碼與對話」]

User: 現在實作一個同時寫入兩個資料庫的雙寫模式

Claude: 我來實作雙寫遷移……
[實作雙寫層、漸進式遷移策略]

User: 執行測試

Claude: 執行測試中……
✅ 所有測試通過

User: 雙寫做法明顯更安全，我們把這個提交吧。
```

## 範例 2：效能最佳化

### 情境
有多種效能最佳化策略可以嘗試。

### 工作流程

```
User: 我們來最佳化 API 回應時間，目前是 450ms
      [自動建立檢查點「基準線」]

Claude: 我來加上資料庫查詢快取……
[實作 Redis 快取]

User: 執行效能測試

Claude: 結果：平均回應時間 280ms（改善 38%）

User: 讓我試試不同的做法。
[使用者按下 Esc+Esc，選取「基準線」檢查點，並選擇「還原程式碼與對話」]

User: 改試資料庫查詢最佳化

Claude: 我來最佳化資料庫查詢……
[新增索引、最佳化 N+1 查詢]

User: 執行效能測試

Claude: 結果：平均回應時間 180ms（改善 60%）

User: 讓我再試第三種做法。
[使用者按下 Esc+Esc，選取「基準線」檢查點，並選擇「還原程式碼與對話」]

User: 試試回應壓縮與 CDN

Claude: 我來加上壓縮與 CDN……
[實作 gzip、設定 CDN]

User: 執行效能測試

Claude: 結果：平均回應時間 320ms（改善 29%）

User: 查詢最佳化的效果最好，讓我回去把它跟快取結合。
[使用者按下 Esc+Esc，選取查詢最佳化之後的檢查點，並選擇「還原程式碼與對話」]

User: 現在在這些最佳化過的查詢上加入 Redis 快取

Claude: [在最佳化過的查詢上加入 Redis 快取]

User: 執行效能測試

Claude: 結果：平均回應時間 95ms（改善 79%）🎉

User: 太棒了！這就是最佳做法，我們提交吧。
```

## 範例 4：除錯工作階段

### 情境
用多個假設追查一個棘手的錯誤。

### 工作流程

```

User: 我覺得問題出在事件監聽器，我們來修吧。

Claude: [修正事件監聽器的清理邏輯]

User: 執行記憶體分析工具

Claude: 記憶體仍在洩漏——問題不是事件監聽器

User: 讓我回去試試不同的假設。

User: 會不會是資料庫連線的問題？

Claude: 仍在洩漏——也不是連線的問題

User: 讓我回去換個角度試試。
[使用者按下 Esc+Esc，選取「除錯前」檢查點，並選擇「還原程式碼與對話」]

User: 我們來檢查循環參照

Claude: [找出並修正快取中的循環參照]

User: 執行記憶體分析工具
```

## 範例 8：從檢查點使用摘要功能

### 情境
經過一段長時間的除錯工作階段（session）後，你想在保留上下文的情況下濃縮對話內容。

### 工作流程

```
User: [經過 20 則以上的除錯與探索訊息之後]

[使用者按下 Esc+Esc，選取一個較早的檢查點，並選擇「從這裡開始摘要」]
[可選擇提供指示：「聚焦在我們嘗試過什麼、哪些方法有效」]

Claude: [產生從該時間點開始的對話摘要]
[原始訊息會保留在逐字稿中]
[摘要會取代可見的對話內容，減少上下文視窗的使用量]

User: 現在讓我們繼續採用有效的做法。
```

## 重點整理

1. **檢查點是自動的**：每次使用者提示都會建立一個檢查點——不需要手動儲存
2. **使用 Esc+Esc 或 /rewind**：這是存取檢查點瀏覽器的兩種方式
3. **選擇適合的還原選項**：依需求還原程式碼、對話、兩者皆還原，或是摘要
4. **不要害怕實驗**：檢查點讓你能安全地嘗試大膽的變更
5. **搭配 git 使用**：用檢查點來探索，用 git 來保存定案的成果
6. **摘要長時間的工作階段**：使用「從這裡開始摘要」讓對話保持在可管理的範圍內
