# Q3｜上百份 Markdown，會找到有答案的那一份嗎？

同學問的是「這次該讀哪幾份」。先用同一題測搜尋路徑。Python 3.9 以上即可建立練習，完全離線；可用編輯器內建的檔案搜尋。

## 第一次，從資料夾找

在本頁所在的資料夾執行：

~~~sh
python3 classroom.py prepare
~~~

指令會產生四個專案，並印出同一個問題。開啟 practice/B-organized，在 docs/ 的兩個框架中選 LangGraph，找出描述節點的文件。**Python 的 CachePolicy 用哪個參數產生快取鍵？用哪個參數設定存活秒數？** 記下兩個參數、原始文件的相對路徑，以及沿途打開幾份檔案。

## 第二次，換入口

| 專案 | 從哪裡開始 | 要記錄什麼 |
| --- | --- | --- |
| A-messy | docs/ 中只有編號，可以用全文搜尋 CachePolicy | 哪個編號有答案？ |
| B-organized | 用框架名稱與主題辨認檔名 | 目錄與檔名能否縮小範圍？ |
| C-indexed | 開啟 INDEX.md，挑一列，依列出的路徑回原文 | 摘要與關鍵字是否幫你選中候選檔？ |
| D-wiki | 開啟 wiki/index.md，選節點快取，跟著概念頁的「出處」讀原文 | 概念頁與原文的說法能否相互核對？ |

每組 docs/ 內三份原文的文字完全一致。組別只改檔名、資料夾、索引或導覽。若有 Claude Code 帳號，可從每個子目錄各開一個新對話，貼下面同一段。記工具開過的檔案、引文與答案；互動呼叫可能產生費用。

> 請只依這個工作目錄內的文件回答。Python LangGraph 的 CachePolicy 要自行決定如何從 node 輸入產生快取鍵，並限制快取存活秒數，分別要填哪兩個參數？請附讀過的原始檔案相對路徑和原文依據。如果找不到，請直接說缺少哪項依據。

## 驗收與延伸

~~~sh
python3 classroom.py verify
~~~

核對原文的兩行：key_func 由節點輸入產生快取鍵，ttl 的單位是秒。四組都要能指出原文。若多次量測工具效率，固定模型與題目，每組另開對話，分開記錄正確率、引用是否命中與工具成本。這個迷你實驗讓你實際走過路徑；人手預先看過答案的時間不適合比較模型。

原實驗用 40 題跑 3 輪；在那次環境中，B 整理目錄的平均花費為每題 US$0.0033，D wiki 為 US$0.0091。新專案先看檔名能否解決問題；讀錯同義詞時，再補入口索引；經常跨多篇綜合時，再評估維護 wiki 的時間。見[原實驗實測報表](experiment-report.md)。
