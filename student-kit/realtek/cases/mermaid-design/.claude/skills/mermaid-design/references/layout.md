# 排版、相容性與驗證

## 修復大空盒的順序

1. 先看最終呈現寬度。原圖 1600px 寬、16px 文字縮到 760px，字會只剩約 7.6px；高解析 PNG 不會讓字在相同顯示尺寸變大。
2. 一般節點選可隨內容縮放的矩形／圓角矩形。避免把說明文字誤用為正方形、圓形、菱形或多層容器。
3. 調整文字：保留決策必需的數值、角色與條件；減少同一節點的行數。兩行短字放進菱形常會製造大量空角。不要機械地刪成不明確的縮寫。
4. 檢查 `flowchart.padding` 的實際效果；不要拿 `nodeSpacing`、`rankSpacing` 或整圖 `diagramPadding` 修節點內部留白。
5. 檢查是否有固定 width/height、過大的最小節點寬度、外部 CSS、字型載入或容器寬度干擾。先移除不必要限制，再重繪。

通常一般節點的文字框應佔有可辨識的比例，但「文字框面積／外框面積」只是啟發式；不等於墨水密度，也不能拿同一門檻評分菱形、圓形、多行與單字節點。

## 佈局決策

- 優先讓成功路徑沿同一方向延伸，將拒絕、退回、補件放在旁邊；不要漏畫回到哪個步驟。
- TB 圖太高且分支只占一側時，試 LR；LR 圖縮小難讀時，試 TB 或拆細節。每個版本都用同一目標寬度比較。
- 圖例、步驟編號與 subgraph 都有閱讀成本，只在有分組或引用需求時使用。少量步驟不要為裝飾而套容器。
- subgraph 的節點連到外部時，局部 `direction` 可能被忽略而繼承主圖方向。不要反覆加方向指令賭結果；改連線或構圖並重新渲染。
- 不用空白節點、透明節點或虛假關係強迫定位。若宿主支援 ELK，可在密集圖中比較它與預設佈局，但不要假設支援。

## 標籤與形狀

範例使用圓角問題節點與條件邊標籤：這是產品風格選擇，不是正式流程圖的通用符號規範。如果使用者要求傳統決策菱形，改為 `check{"資料齊全？"}` 並重新評估空間。

優先使用有引號的簡短標籤 `step("提交申請")`。需要換行時：

- 支援 Markdown strings 的渲染器可用反引號包裹的標籤與真正換行，並檢查自動換行結果。
- 傳統標籤常用 `<br/>`，但不同宿主的 HTML 支援不同。不要假設普通字串的 `\n` 必定換行。
- `wrappingWidth` 是特定標籤／渲染方式的文字換行寬度，不是所有節點的固定寬度。不要為統一外框而濫用它。

## 相容性分層

先使用目標支援的基本節點、邊與 `classDef`；再加可用的圖級設定。宿主不明時使用範例的保守語法，不依賴新版本功能。

範例採 YAML frontmatter `config`、`theme: base`、`themeVariables` 和傳統形狀；在本次驗證的 Mermaid CLI 11.4.2（Mermaid 引擎 11.6.0）可渲染。官方文件會隨版本更新，不代表宿主同步升級。不要為使用此 skill 自動升級專案依賴。

如果宿主不接受 frontmatter，可在已確認支援時使用 `%%{init: {...}}%%`；若兩者都被移除，保留基本圖與 `classDef`，重新驗證，說明主題／內距可能退回宿主預設。沒有目標平台權限時交付本機預覽，不宣稱跨平台一致。

`htmlLabels: false` 可減少 SVG 對 HTML foreignObject 的依賴；字型仍會影響中文字寬與換行。優先使用目標系統已安裝的 CJK 字型，不為預覽擅自下載遠端字型或變更全域設定。深色文件需另調背景與對比並看圖。

## 助手與限制

`scripts/render.mjs` 會從 PATH 或 `--mmdc` 找到既有 CLI，使用該安裝可解析的 Puppeteer。瀏覽器依序使用明確設定、Puppeteer 現有瀏覽器、macOS 已安裝的 Google Chrome、PATH 中的 Chrome/Chromium；找不到會清楚回報，不會下載瀏覽器。可傳入 `--puppeteer-config browser.json` 使用與 CLI 相同的設定，例如 `{"executablePath":"實際既有瀏覽器執行檔路徑"}`。不要為了讓它跑起來任意關閉 sandbox 或改安全設定。

報告的字級以 SVG 寬度縮到指定容器且不放大的情境估算；不模擬宿主額外的高度限制、外部 CSS 或字型替換。節點框重疊可自動提示，但箭頭穿字、曲線碰撞、文字完整性和閱讀動線仍需看圖。比較版本時固定寬度，不用不同縮放製造改善印象。
