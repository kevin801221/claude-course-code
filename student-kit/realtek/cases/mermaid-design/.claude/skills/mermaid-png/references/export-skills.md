# 格式入口的共用設計與交付

五個入口共用本機腳本、產品風格與看圖驗收；選擇依使用者所需成品：

| 請求 | 入口 | 公開成品 |
| --- | --- | --- |
| Mermaid 流程圖設計、美化，未指定輸出格式 | `mermaid-design` | 原始碼與同版預覽 |
| PNG、點陣圖或文件圖片 | `mermaid-png` | `.mmd`、PNG |
| SVG、向量圖或網頁嵌入 | `mermaid-svg` | `.mmd`、SVG |
| PDF、可列印文件 | `mermaid-pdf` | `.mmd`、PDF |
| 可編輯 PowerPoint、PPT／PPTX 或三格式同步包 | `mermaid-ppt` | `.mmd`、PNG、SVG、原生 `.pptx` |

使用者明確指定的額外格式優先；PNG+SVG 但沒有簡報需求時，可用相同來源執行 `--formats png,svg`。不要因為「SVG 向量」而推論使用者要求 PowerPoint。

## 共用產品風格

白底或文件指定底色、柔和圓角、低飽和填色、深色文字、適度留白、一致的關鍵路徑。使用者的品牌風格與正式製圖規範優先。中文預設繁體，專有名詞保留。從 [產品風格範例](../assets/product-flow.mmd) 起步。

1. 保留必要節點、條件、數字、分支、先後與回路，不能為整齊刪除例外路徑或改變語意。每節點一個動作或問題，通常一行、必要時兩行；不影響判斷的解說移到圖外。
2. 已知時採用實際容器寬度；未知時先以 760 CSS px 文件寬度檢查。短流程試 LR，長流程或多分支試 TB。出現細長圖、大空洞、交叉或縮小後難讀，實際比較另一方向。先改構圖，必要時拆總覽與細節並保留對應。
3. 一般短節點自然貼合文字，多呈扁長形；不固定所有節點寬高，不塞空白、不逐字斷行。原始字級可從 16–18px 開始，最終顯示盡量不低於 14px。產品圖可用圓角問題節點加條件邊標籤；使用者要求正式菱形時保留菱形並看圖調整。
4. 關鍵路徑使用一個主色，其他節點中性；綠／紅只表達成功／拒絕等語意。分支有文字，不只靠顏色。`nodeSpacing`／`rankSpacing` 影響節點間距，不能拿來修節點內部空盒。

換行、字型、`subgraph` 方向、配置與平台限制，讀 [排版與相容性](layout.md)。不要為預覽擅自下載遠端字型、變更全域設定或關閉瀏覽器 sandbox。

## 渲染與驗收

開啟實際成品，在最終呈現尺寸檢查全部文字、箭頭、分支、回路與留白。文字裁切、重疊、方向不明、漏分支、字型缺字或縮小後難讀，必須修正並重繪；明顯構圖問題至少實際比較一個替代版。高解析度不會讓同一顯示尺寸中的字變大，數值報告不能取代看圖。

SVG 無法直接查看時，用同份 `.mmd`、相同設定產生 QA 預覽：

```sh
node <skill-dir>/scripts/render.mjs diagram.mmd --out work/qa-diagram --width 760
```

開啟 `work/qa-diagram.png`；暫存檔不作為額外交付。PPTX 還需逐頁檢查實際投影片與原生物件，不能以來源 PNG 的觀感代替。修正來源後，重匯出本次要求的全部格式。

交付最終 `.mmd` 與同一版成品，簡述實際驗證的渲染器、寬度、投影片頁面與限制。無法開圖就標示「尚未完成視覺驗證」；無法查看 PPTX 就標示「尚未完成 PPTX 視覺驗證」。不宣稱未驗證的平台呈現一致。

## 本機環境

執行匯出腳本前檢查現有 Node.js、`mmdc`、Puppeteer 與可用 Chrome／Chromium；PPTX 額外檢查所選 Python 的 `python-pptx`。不自動安裝或更新；缺件時提供具體安裝指令，保留可交付的 `.mmd`，不宣稱匯出成功。參數以 `node <skill-dir>/scripts/export.mjs --help` 為準。所有入口可在 Claude Code、Codex 與 Gemini 的本機環境使用，不要求專有雲端工具。
