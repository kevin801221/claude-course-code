# Q4｜結束對話以後，怎麼證明工作記憶真的找得回來？

11/16 有人回報重複報名，11/17 有新的測試。新對話問「這件事後來怎麼了」，只要命中第一筆回報就回答，便會錯過驗證結果。我們先練習「留下來源 → 搜尋索引 → 看前後 → 取出原文」。

## 關掉第一個程序，再讀一次

以下每一行都是獨立的程序。即使先關掉終端機，只要重新進入本頁所在目錄再查，也會讀到同一份 practice/memory.sqlite3。練習使用 Python 3.9 以上，完全離線。

~~~sh
python3 classroom.py save
python3 classroom.py search 重複報名
python3 classroom.py timeline 102
python3 classroom.py get 102
~~~

1. save 從 fixtures/observations.json 保存 4 筆有 ID 的觀察。重跑仍是這 4 筆。這個示範把保存動作明確做出來，便於確認哪個時間點已落盤。
2. search 列出 #101 和 #102 的日期、主題、狀態。timeline 讓你在同一主題內看到兩次紀錄。#101 是初報，#102 才有回歸測試。
3. get 102 回傳完整內容與 TEST-12。到[合成證據](fixtures/evidence.md)核對同一人送兩次後，資料庫筆數為 1。
4. 試著搜尋一個完全沒寫入的詞。結果會是「查無這個詞的記憶」。執行 python3 selfcheck.py 可驗收關閉程序後保存、重讀和每日／週報的結果。

## 在實際專案，該存什麼？

未確認的猜測保留在當下的工作討論；需要交接的決定，保存「日期、結論、適用範圍、來源」。正式需求或測試結果放回有版本的文件，記憶只需留可追溯的索引。對話壓縮後，開新對話做一次檢索演練；能取回正確紀錄、打開來源並核對內容，才算通過。

若已在 Claude Code 連上第三方 claude-mem，將下面貼在另一個新對話，換成自己的專案與關鍵字。真實 observation ID 由該安裝產生；前面的 101、102 只屬課堂 SQLite，教學腳本也不會寫入外掛。

> 請用 claude-mem 搜尋這個專案中與「重複報名」有關的 observation。先列出命中的 ID 與日期，再看最近已驗證那筆的前後紀錄，最後只取相關 ID 的完整內容，告訴我結論和可核對的檔案或測試。找不到就說缺少哪項證據。

實際搜尋需要可用的外掛、記憶擷取服務和已保存的資料。軟體的 search、timeline、get_observations 用法也可從[講師原始 Prompt](upstream/prompts/daily-report.md)跟讀。Q2 與 Q4 共用來源版本 23ede238b63004166a01299b45911f1c4f87036e。[跨對話記憶實作與架構](https://github.com/kevin801221/claude-mem-application_/tree/23ede238b63004166a01299b45911f1c4f87036e)
