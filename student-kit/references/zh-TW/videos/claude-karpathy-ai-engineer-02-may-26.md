## 逐字稿

### 開場

我們非常興奮迎來第一位特別來賓。他協助打造了現代 AI，接著解釋現代 AI，偶爾還重新命名現代 AI。他就在這間辦公室裡協助共同創辦了 OpenAI，當年也是真正讓 Tesla Autopilot 運作起來的人。他有一種罕見的天賦，能讓最複雜的技術轉變同時顯得平易近人又理所當然。各位都知道他去年創造了 vibe coding 這個詞，但就在最近幾個月，他說了更令人吃驚的話：他從未如此覺得自己身為程式設計師是落後的。我們今天就從這裡開始。謝謝 Andrej 來參加。

嗨，很高興來這裡為大家開場。

### 「從未如此覺得自己身為程式設計師是落後的」

好，就在幾個月前，你說你從未如此覺得自己身為程式設計師是落後的。從你口中聽到這句話特別令人吃驚。能幫我們拆解一下嗎？那種感覺是振奮還是不安？

兩者都有，肯定的。首先，跟很多人一樣，我用 Claude Code 這類 agentic 工具已經有一陣子了，大概是過去一年它推出以來。它處理程式碼片段的能力很好，有時會搞砸，你得去改，大致算有幫助。然後我會說十二月是一個明確的轉捩點 —— 當時我在放假，時間比較多。我想很多人情況類似 —— 我開始注意到，用最新的模型時，那些片段就是直接出來就對了，然後我繼續要求更多，它還是直接就對了，然後我已經想不起來上一次修正它是什麼時候。接著我越來越信任這套系統，然後我就在 vibe coding 了。

所以那是個非常劇烈的轉變。我想其實很多人 —— 我在 Twitter（或說 X）上試著強調這點 —— 因為我覺得很多人去年體驗的 AI 是 ChatGPT 那一類的東西。但你真的得重看一次，而且要從十二月開始重看，因為事情已經根本性地改變了 —— 特別是在這種 agentic、連貫的工作流上，它真的開始能用了。所以我會說，就是那個領悟讓我一頭栽進無窮無盡的副專案裡。我的副專案資料夾塞滿了各種隨機的東西，然後就一直 vibe coding。這大概是十二月發生的，之後我一直在觀察它的後續影響。

### Software 3.0：新的運算典範

你談過很多「LLM 是一種新電腦」的想法。它不只是更好的軟體，而是一個全新的運算典範。Software 1.0 是明確的規則，software 2.0 是學習而來的權重，software 3.0 就是這個。如果這是真的，一個團隊在真正相信這件事的那天，會開始做哪些不一樣的事？

對。Software 1.0 是我在寫程式碼，software 2.0 是我透過建立資料集與訓練神經網路來編程。所以編程變成像是整理資料集，也許加上一些目標函式與神經網路架構。然後發生的事是：如果你在足夠大量的任務上訓練這些 GPT 模型或 LLM —— 隱含地，因為在網路資料上訓練就必須同時處理資料集裡所有的事 —— 它們在某種意義上就變成了一台可編程的電腦。

所以 software 3.0 大概是說，你的編程現在變成了下 prompt，而脈絡視窗裡的內容就是你操控那個「直譯器」的槓桿 —— 那個直譯器就是 LLM，它詮釋你的脈絡並在數位資訊空間中執行運算。

有幾個例子讓我真正體會到這點。例如 OpenClaw 推出時，你要安裝 OpenClaw，正常會預期那是個 bash 腳本、shell 腳本。跑那個 shell 腳本來安裝 OpenClaw。但問題是，為了支援各式各樣的平台與各種你可能執行 OpenClaw 的電腦，這些 shell 腳本通常會膨脹到極度複雜。而且你仍然卡在 software 1.0 的宇宙裡，想要去寫出那段程式碼。但實際上，OpenClaw 的安裝方式是複製貼上一段文字給你的代理。所以它基本上是個小 skill：「複製這段貼給你的代理，它就會安裝 OpenClaw。」這之所以強大得多，是因為你現在是在 software 3.0 典範中工作 —— 你不必精確地寫出那套設定的每一個細節。代理有自己的智慧，它把這些打包起來，然後照著指示做、觀察你的環境與電腦，執行聰明的動作讓事情能動，並在迴圈中除錯。這就是強大太多了。所以那是一種非常不同的思考方式 —— 要複製貼給你代理的那段文字是什麼？那就是編程典範。

### MenuGen 與「不該存在的 App」

我想到另一個比這更極端的例子，是我在打造 MenuGen 的時候。MenuGen 的概念是：你到餐廳，他們給你一份菜單，通常沒有圖片。我完全不知道那些東西是什麼 —— 通常有 30%、甚至 50% 的品項我根本不知道是什麼。所以我想拍一張餐廳菜單的照片，然後取得這些東西大概長什麼樣的圖片。

我 vibe-code 出一個 App，基本上讓你上傳照片，它做完所有處理，跑在 Vercel 上，重新渲染菜單、列出所有品項，用 OCR 辨識出各個標題，再用圖片生成器取得它們的圖片然後顯示給你。

然後我看到了這件事的 software 3.0 版本 —— 這讓我大開眼界 —— 那就是：直接拍照，交給 Gemini 說「用 Nanobanana 把那些東西疊到菜單上」。Nanobanana 基本上回傳了一張圖，正是我拍的那張菜單照片，但它真的把那些品項渲染進了像素裡。這讓我震驚，因為我整個 MenuGen 其實是多餘的。它是在舊典範裡運作的。那個 App 根本不該存在。

Software 3.0 典範更加原始直接。你的神經網路做掉越來越多工作，而你的 prompt 或脈絡就只是那張圖，輸出也是一張圖，中間根本不需要任何 App。所以人們必須重新框定 —— 不要在既有典範裡工作、只把它當成既有事物的加速。現在有新的東西可以做了。

回到你關於編程的問題，這甚至不只是 —— 我想那也是舊思維的一個例子，因為這不只是編程、不只是編程變快。這是更廣義的資訊處理，現在變得可自動化了。所以它甚至不只關乎程式碼。以前的程式碼是在結構化資料上運作的，對吧？你在結構化資料上寫程式。但例如我的 LLM 知識庫專案 —— 基本上是讓 LLM 為你的組織或你個人建立 wiki —— 這甚至不是一支程式。這不是以前可能存在的東西，因為沒有任何程式碼能根據一堆事實建出一個知識庫。但現在你可以把這些文件拿來，用不同方式重新編譯、重新排序，創造出一個對資料的重新框定、既新穎又有趣的東西。這些是以前不可能的新事物。所以我一直想拉回來談的是：不只是「以前存在的東西現在變快了」，我覺得更令人興奮的是「有一整批以前根本不可能的新機會」。

### 外推到 2026 年與更遠

我很喜歡你鋪陳的 MenuGen 演進與對比。如果再往下外推，2026 年會出現什麼，相當於 90 年代建網站、2010 年代做手機 App、上個雲端時代做 SaaS 的那種東西？有什麼事今天幾乎還沒人做，但事後回看會覺得完全理所當然？

延續菜單那個例子，很多程式碼根本不該存在，大部分工作就讓神經網路做。我確實覺得外推出來的樣子很怪，因為你幾乎可以想像某種意義上的「全神經電腦」。你餵進原始影像 —— 想像一個裝置把原始影像或音訊送進一個基本上就是神經網路的東西 —— 然後用 diffusion 渲染出一個在那個當下獨一無二的 UI。

我有種感覺，在運算早期，人們其實有點搞不清楚電腦會長得像計算機還是像神經網路。在 50、60 年代，走哪條路並不明顯。當然我們走了計算機那條路，建立了古典運算，而神經網路目前是在既有電腦上虛擬執行。但我認為這很多會翻轉過來：神經網路成為主行程，CPU 變成共處理器。我們已經看到神經網路的智慧運算將會接管，成為 FLOPs 的主要支出。所以你可以想像某種非常怪、非常陌生的東西，神經網路承擔大部分重活，它們把工具使用當成某種歷史遺留的附屬器官，處理某些確定性任務。但真正主導全局的是這些神經網路。所以外推出來可以是極其陌生的東西，但我想我們大概會一塊一塊地走到那裡。

### 可驗證性與鋸齒狀智慧

我想談談「可驗證性」這個概念 —— 也就是 AI 會在輸出可被驗證的領域自動化得更快更容易。如果這個框架正確，有哪些工作即將比人們意識到的更快被加速？又有哪些職業人們以為安全、實際上卻高度可驗證？

我花了一些時間寫關於可驗證性的東西。基本上，傳統電腦能輕易自動化你能用程式碼明確指定的事，而這一輪 LLM 能輕易自動化你能驗證的事。某種意義上是因為：前沿實驗室訓練這些 LLM 的方式是巨大的強化學習環境。它們被給予驗證式獎勵，而因為這種訓練方式，模型最後變成這些鋸齒狀的實體 —— 在數學、程式碼及鄰近的可驗證領域能力飆高，而在那之外的事情上停滯、邊緣粗糙。

所以我寫可驗證性，是想理解為什麼這些東西這麼鋸齒。部分跟實驗室怎麼訓練模型有關，但我想也有部分跟實驗室的重心、以及他們剛好放進資料分布裡的東西有關。因為有些事在經濟上價值顯著更高，於是衍生出更多環境，因為實驗室想在那些場景中運作。我想程式碼就是個好例子。大概還有很多可驗證的環境他們本來能想到，只是剛好沒進到這鍋裡，因為擁有那個能力沒那麼有用。

最大的謎團 —— 有一陣子大家最愛的例子是「strawberry 有幾個字母」，模型出了名地會答錯，那是鋸齒性的一個例子。我想模型現在已經補上了。但新的例子是：「我想去洗車，洗車場離我 50 公尺。我該開車還是走路？」今天最先進的模型會告訴你走路去，因為很近。怎麼可能最先進的 Opus 4.7 能重構十萬行的 codebase、能找出 zero-day 漏洞，卻叫我走路去洗車？這太荒謬了。

只要這些模型還是鋸齒狀的，那就代表：第一，也許有什麼地方不太對；第二，你確實需要留在迴圈裡一點，得把它們當工具看待，必須保持對它們在做什麼的掌握。所以我關於可驗證性的所有寫作，長話短說，就是想理解這些東西為什麼鋸齒。其中有規律嗎？我想那是「可驗證」加上「實驗室在乎」的某種組合。

再講一個有啟發性的軼事：從 GPT-3.5 到 GPT-4，人們注意到西洋棋能力進步很多，很多人覺得「喔那只是能力的自然進展」—— 但實際上更多是因為大量的西洋棋資料進了預訓練集，而光是因為它在資料分布裡，模型就比預設情況進步得多很多。所以是 OpenAI 的某個人決定加進這批資料，於是你就有了一個明顯飆高的能力。

所以我才強調這個面向：我們多少受制於實驗室在做什麼、他們剛好把什麼放進這鍋裡。而你得去探索這個他們給你的、沒有說明書的東西。它在某些場景能動，在某些場景可能不行。如果你落在 RL 涵蓋過的迴路裡，你就會飛起來。如果你落在資料分布之外的迴路，你就會很掙扎，而你得搞清楚自己的應用落在哪些迴路裡。如果不在那些迴路裡，你就真的得考慮 fine-tuning、做一些自己的工作，因為那不見得能從 LLM 開箱就跑出來。

### 給創辦人的建議

如果你今天是創辦人，想創立一家公司，想解決一個你認為可解的問題、在一個可驗證的領域，但環顧四周你會想：「天啊，實驗室在那些最明顯的領域 —— 數學、寫程式之類 —— 已經快要達到逃逸速度了。」你對在場的創辦人有什麼建議？

我確實認為可驗證性讓一件事在當前典範中變得可解，因為你可以砸大量 RL 進去。所以一種看法是：即使實驗室沒有直接聚焦在那裡，這件事仍然成立。如果你處在一個可驗證的場景，能建立這些 RL 環境或範例，那其實就讓你有機會做自己的 fine-tuning，並從中受益。這根本上就是一項「確實有效」的技術。只要你有大量多樣的 RL 環境資料集，你就能拉這根槓桿，用你愛用的 fine-tuning 框架，拉下去就能得到效果相當好的東西。

我確實認為有一些非常有價值的強化學習環境是人們想得到、但我認為不在［實驗室的重心］裡。我不想直接公布答案，但有一個領域我認為非常［有價值］。抱歉，我不是故意在台上講得很模糊，但這類例子是存在的。

反過來說，你覺得哪些事只有「遠看」才像是可自動化的？

我確實認為，終究幾乎所有事都能在某種程度上被變得可驗證 —— 有些比較容易，有些比較難。因為即使是寫作之類的事，你也可以想像用一組 LLM 評審團，大概能從這種做法得到還不錯的結果。所以重點更在於難易，而不是可不可能。我想終究一切都可自動化。

### Vibe Coding vs Agentic Engineering

去年你創造了 vibe coding 這個詞，而今天我們處在一個感覺更嚴肅一點的世界 —— 更像 agentic engineering。你覺得兩者的差別是什麼？你會怎麼稱呼我們現在所處的狀態？

好。我會說 vibe coding 是在提高每個人在軟體上能做到什麼的「地板」。地板升高了，每個人都能 vibe code 任何東西，這很棒、很不可思議。但我會說 agentic engineering 是在守住專業軟體原本就有的品質標準。你不能因為 vibe coding 就引入漏洞。你對自己的軟體仍然要負責，跟以前一樣，但你能不能更快？劇透：可以。但要怎麼做得對？所以對我來說，agentic engineering —— 我這樣稱呼它，因為我確實認為它是一門工程學科 —— 你有這些代理，它們是尖峰狀的實體，有點容易出錯、有點隨機，但極其強大。你要怎麼協調它們來加速，同時不犧牲你的品質標準？把這件事做好、做對，就是 agentic engineering 的範疇。

所以我把它們看成不同的東西 —— 一個是提高地板，另一個是往上外推。而我看到的是，agentic engineer 能力的天花板非常高。以前人們談 10x 工程師 —— 我認為這被放大得更多。10x 不是你得到的加速幅度。從我現在的角度看，很擅長這件事的人，拉開的差距遠不只 10 倍。

### AI 原生的寫程式長什麼樣

Sam Altman 去年來 AI Engineer 時說過一句讓人印象深刻的話：不同世代的人用 ChatGPT 的方式不同。三十幾歲的人把它當 Google 搜尋的替代品；但如果你是青少年，ChatGPT 就是你通往網路的入口。在今天的寫程式上有什麼對應？如果我們看兩個人用 OpenClaw、Claude Code、Codex 寫程式 —— 一個你會覺得普普，一個你會覺得完全 AI 原生 —— 你會怎麼描述那個差別？

我想就是盡可能榨出手上工具的最大價值 —— 用好它們所有功能、投資在自己的設定上。就像以前所有工程師基本上都在榨出自己所用工具的最大價值 —— 不管是 Vim、VS Code，還是現在的 Claude Code 或 Codex —— 投資你的設定、用好手上大量可用的工具。我想大概就長那樣。

一個相關的想法 —— 現在很多人大概正在為此招人，因為他們想招到強的 agentic engineer。我確實認為多數人還沒有為「agentic engineer 能力」重構自己的招募流程。如果你還在出解謎題，那還是舊典範。我會說招募應該長成這樣：給我一個真的很大的專案，看某個人把那個大專案實作出來。例如我們來寫一個給代理用的 Twitter 複製品，然後把它做得很好、很安全，再讓一些代理在這個 Twitter 上模擬活動，接著我會用 10 個 Codex 5.4x 開 xhigh 去試著打破你部署的網站，它們會試著打破它，而它們應該打不破。大概長那樣吧。看人在那種情境下建更大的專案、用好工具鏈，大概就是我主要會看的東西。

### 品味、判斷，以及留在迴圈裡的人

當代理做得越來越多，你認為哪些人類技能會變得更有價值而非更無價值？

現在的答案是，這些代理有點像實習生實體。所以很了不起的是 —— 你基本上仍然得負責美感、判斷、品味，以及一點監督。

我最愛的代理怪異行為例子之一是 —— 在 MenuGen 裡，你用 Google 帳號註冊，但用 Stripe 帳號購買點數，兩者都有 email 地址。我的代理在處理購買點數時，實際上是用 Stripe 的 email 地址去對應 Google 的 email 地址 —— 就像根本沒有持久的 user ID 一樣。對使用者來說，它想用 email 地址去配對，但你的 Stripe 和 Google 可能用不同 email，那樣就根本不會把款項關聯起來。這就是這些代理仍然會犯的那種錯 —— 為什麼你會用 email 地址去交叉比對款項？那是可以任意填的。你可以用不同的 email。這做法實在太怪了。

所以我認為人必須負責這份規格、這份計畫。而我其實連 plan 模式都不太喜歡。它當然很有用，但我覺得這裡有個更普遍的東西：你得跟你的代理一起設計一份非常詳細的規格 —— 大概基本上就是文件 —— 然後讓代理去寫，而你負責監督與頂層分類，代理則處理很多底層細節。所以你不必在意某些細節。

再舉個例子，神經網路裡的陣列或張量。PyTorch、NumPy 以及各種 —— Pandas 等等之間有一堆 API 細節差異。我已經忘了 keep_dims 還是 keep_dim、是 `dim` 還是 `axis`、是 reshape 還是 permute 還是 transpose。我不再記這些東西了。因為你不必記。這類細節就交給實習生處理，因為他們的記憶力很好。但你仍然得知道，例如底下有一個張量、有一個 view，你可以操作同一塊儲存的 view，或者用不同的儲存（那會比較沒效率）。所以你仍然得理解這些東西在做什麼、懂一些基本功，才不會不必要地到處複製記憶體。但 API 的細節現在交出去了。所以你負責品味、工程、設計 —— 確保它合理、確保你要的是對的東西。像是：好，這些必須是唯一的 user ID，所有東西都綁在上面。所以你做部分的設計與開發，工程師（代理）做填空。這就是我們目前所在的位置。

你覺得這份品味與判斷有可能隨時間變得不那麼重要，還是天花板會一直升高？

我希望它會進步。我想它現在沒進步的原因，同樣是：它不在 RL 的範圍內。大概沒有美感的成本或獎勵，或者還不夠好之類的。我確實覺得，當你真的去看程式碼，有時會有點心臟病發，因為它不見得總是超棒的程式碼。它很臃腫、很多複製貼上、有些彆扭又脆弱的抽象，能動，但就是很噁心。我真心希望未來的模型能改善這點。

另一個好例子是 microGPT 專案，我想把 LLM 訓練簡化到最簡單的程度。模型討厭這件事。它們做不到。我不斷 prompt LLM 再簡化、再簡化，它就是做不到。你會感覺自己在 RL 迴路之外。感覺像在拔牙，不是光速。所以我確實認為人仍然得負責這件事。但這沒有什麼根本性的阻礙，幾乎只是實驗室還沒去做而已。

### 動物 vs 幽靈：理解 LLM 到底是什麼

我想回到鋸齒狀智慧這個想法。你寫過一篇很發人深省的文章，談動物與幽靈。那個想法是：我們不是在打造動物，我們是在召喚幽靈。而這些是由資料與獎勵函式塑造的鋸齒狀智慧，而不是由內在動機、樂趣、好奇心或自主感塑造的 —— 那些是演化帶來的東西。為什麼這個框架重要？它實際上改變了你如何打造、部署、評估甚至信任它們？

我寫這個是因為我試著弄清楚這些東西到底是什麼。因為如果你對它們「是什麼、不是什麼」有好的模型，你用起來就會更稱職。我不確定它是否真的有實用威力，我想那有點哲學思辨的成分。但那就是去接受一個事實：這些東西不是動物智慧。像是你對它們大吼，它們不會做得更好或更差 —— 沒有任何影響。那全都是統計模擬迴路，底層基質是預訓練（也就是統計），再把 RL 疊上去，增加一些附屬器官。也許那只是我進入狀況時的一種心態，或者是「什麼可能有效、什麼可能無效、要怎麼調整」。但我其實沒有「讓你系統變好的五個明顯做法」。它更像是對它保持懷疑，並隨時間摸索。那是起點。

### Agent 原生的基礎設施

好，你跟代理合作得非常深入 —— 那些不只是聊天的代理，它們有真正的權限、有本機脈絡，真的會代替你行動。當我們都開始活在那個世界時，世界會長什麼樣？

我想這裡很多人大概都對「agent 原生的 agentic 環境」長什麼樣很興奮。一切都得重寫。所有東西基本上仍是為人類而寫的，必須被搬動。我大多數時候用不同的框架或函式庫時，它們的文件根本上還是寫給人看的。這是我最常碎念的點。為什麼人們還在告訴我該做什麼？我什麼都不想做。我該複製貼給我代理的東西是什麼？每次被告知「去這個 URL」之類的，我就覺得啊——。

每個人都很興奮於：我們要怎麼把必須發生的工作負載，拆解成對世界的感測器與致動器？我們要怎麼把它變成 agent 原生？基本上就是先對代理描述它。然後圍繞著對 LLM 極易讀的資料結構做大量自動化。

MenuGen 有個很有名的例子，我寫那篇部落格文章時 —— 很多麻煩甚至不是在寫 MenuGen 的程式碼，而是把它部署到 Vercel，因為我得跟各種不同服務打交道、把它們串起來、進它們的設定與選單、設定我的 DNS，有夠煩。所以那是個好例子：我會希望 MenuGen 這件事，我只要給 LLM 一個 prompt「build MenuGen」，然後我什麼都不用碰，它就同樣部署到網路上了。我想那會是個好測試，看我們的基礎設施是不是越來越 agent 原生。

終究我確實認為我們正走向一個「人與組織都有代理代表」的世界。「我讓我的代理跟你的代理談」來敲定會議之類的細節。所以我確實認為大致方向是那樣。

### 教育：可以外包思考，不能外包理解

我想我們得用一個關於教育的問題作結。因為你大概是世界上最擅長把複雜技術概念講簡單的人之一，也對如何圍繞它設計教育有很深的思考。當智慧變得便宜、我們進入 AI 的下個時代時，什麼仍然值得深入學習？

最近有一則推文讓我大受震撼，我大概每隔一天就會想起它。大意是：**「你可以外包你的思考，但你不能外包你的理解。」**

我覺得這說得真好。因為我仍然是系統的一部分，我仍然得以某種方式 —— 資訊仍然必須進到我的腦子裡 —— 而我感覺自己正在成為瓶頸，光是「知道我們在試著打造什麼、為什麼值得做、我要怎麼指揮我的代理」這些事。所以我確實認為，終究得有某個東西來指揮思考與處理，而那仍然根本性地受到「理解」的約束。

這也是我對那些 LLM 知識庫這麼興奮的原因之一 —— 因為我覺得那是我處理資訊的方式。每當我看到對資訊的不同投影，我總覺得自己獲得了洞見。所以那其實只是我拿一批固定資料做合成資料生成的大量 prompt。每當我讀一篇文章，我都很享受 —— 我有一個從這些文章累積起來的 wiki，我很愛對裡面的東西提問。我認為這些終究是以某種方式增強理解的工具。而這仍然是個瓶頸，因為你沒有理解就無法指揮、無法當個好導演 —— 因為 LLM 顯然不擅長理解，你仍然是唯一負責那件事的人。所以這類用途的工具，我認為非常有趣也令人興奮。

我很期待過幾年再回到這裡，看看我們是不是已經被完全自動化出迴圈之外，連理解也由它們包辦了。非常感謝你來參加，Andrej。我們真的很感激。
