# 週報輸出範本（黃金格式）

## 標準格式（給工程主管 / 同層級）

```markdown
# 📅 週報 — YYYY-MM-DD
> 期間：YYYY-MM-DD ~ YYYY-MM-DD · 作者：你的名字

## ✨ 重點完成（這週對使用者影響最大的 3-5 件）
- (一句話講做了啥) — (一句話講對使用者的影響)
  例：上線「批次匯入」功能 → 客戶不用再一筆一筆建立資料

## 🐛 主要修復
- (修了哪個 bug) — (誰受影響、多嚴重)
  例：修復 Safari 上登入失敗的問題（影響約 8% 用戶）

## ♻️ 內部優化（一句話帶過，使用者無感）
- 重構 auth 模組、優化 dashboard query 速度

## 📌 進行中 / 下週重點
- (還沒完成的工作) — (預計何時完成)
- (下週要開始的) — (為什麼這個優先)

## 🚧 需要幫忙 / Blockers（如果有）
- (卡住的事 + 你需要誰做什麼)
```

## 給非技術主管的格式（CEO / 客戶版）

把上面的「✨ / ♻️」全部刪掉，只留「使用者影響」那段：

```markdown
# 📅 本週進度 — YYYY-MM-DD

## ✅ 上線了
- 「批次匯入」功能 → 大客戶現在可以一次上傳 1000 筆資料
- 修了 Safari 登入問題 → 8% 用戶終於能正常使用

## 🚧 下週重點
- 完成計費系統整合（預計週四上線）

## 📊 數字
- 本週修復 5 個 bug、上線 2 個功能
- 線上錯誤率從 0.8% 降到 0.3%
```

## 翻譯對照表（工程術語 → 使用者語言）

| 工程術語 | 使用者語言 |
|---|---|
| Refactor `XxxService` | 「內部優化（無外觀變化）」 |
| Fix N+1 query | 「優化頁面載入速度（從 X 秒 → Y 秒）」 |
| Add unit tests | 「補測試覆蓋（提升穩定度）」 |
| Migrate to v2 API | 「升級底層 API（為下個功能鋪路）」 |
| Bump dependencies | 「安全性更新」 |
| Add monitoring | 「加上故障偵測（出問題能更快發現）」 |
| Refactor `auth.ts` | 「整理登入相關程式碼」 |
| Fix race condition | 「修復偶發性錯誤（影響少數用戶）」 |
| Optimize bundle size | 「減少 App 載入流量（行動裝置使用者受惠）」 |
