# 反例：什麼絕對不能寫

## ❌ 反例 1：commit 直接 dump

```
本週做了：
- abc1234 Refactor AuthMiddleware.parseToken
- def5678 Fix typo in Button.tsx
- 9012345 Update package.json
- 6789abc Bump axios from 1.5 to 1.6
- def0123 Add console.log for debugging
```

**問題**：讀者完全不知道發生了什麼、有沒有意義、有沒有風險。

**修正**：合併、翻譯、刪不重要的。

```
本週重點：
- 修復登入 token 驗證的潛在安全問題（影響 admin 權限）
- 升級依賴 + 補幾個小修正
```

---

## ❌ 反例 2：自吹自擂

```
本週成果豐碩！我成功完成了：
- 困難的 X 重構（這個非常有挑戰性）
- 巧妙的 Y 解法（用了一個聰明的技巧）
- ...
```

**問題**：讀者只想知道做了什麼、有沒有用，不想看你的 ego。

**修正**：陳述事實，影響交給讀者判斷。

---

## ❌ 反例 3：技術細節爆炸

```
本週把 OAuth flow 從 implicit grant 改成 PKCE，
新增 nonce 驗證以防止 CSRF，並且把 token storage
從 localStorage 改成 httpOnly cookie 以避免 XSS...
```

**問題**：除非讀者是 security engineer，否則沒人看得懂或在意。

**修正**：

```
本週升級登入安全性 → 符合最新業界標準（無使用者感知變化）
```

---

## ❌ 反例 4：列「進行中」當成果

```
✨ 本週完成
- 開始研究 X 系統
- 開始設計 Y feature
- 開始討論 Z 架構
```

**問題**：「開始」不算成果，會讓讀者覺得這週都在做白工。

**修正**：要嘛有可量化成果（spike doc、POC、決策）才寫，要嘛挪到「進行中」。

---

## ❌ 反例 5：硬湊滿格式

```
## ✨ 新功能
- (本週無)

## 🐛 Bug 修復
- (本週無)

## ♻️ 內部優化
- (本週無)
```

**問題**：所有人都看得出你想用格式湊版面。

**修正**：直接寫「本週主力在 X（會議 / 規劃 / debug 卡關），下週開始實作」。誠實比格式重要。
