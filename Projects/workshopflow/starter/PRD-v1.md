# WorkshopFlow｜共同規格 v1

【PM 統一回答卡】
業務目標：讓學員知道報名狀態，HR 不再手動數人和追候補；驗收以正確性與可操作性為主，不預設改善百分比。
角色：HR 管理員與學員。學員有 internal／external 類別；v1 兩類的報名規則相同。使用 6 個本機種子身分：1 位 HR、3 位內部學員、2 位外部學員。這是教學身分模擬，沒有真實認證，不可部署為正式登入系統。即使模擬身分，伺服器仍須檢查 HR 角色與操作擁有權。
畫面：場次列表、場次詳情與報名、我的報名、HR 管理。場次含名稱、說明、開始時間、正整數容量與報名是否開放。HR 可建立、調整容量與關閉報名；不得將容量調到已正取人數以下；增加容量時在同一交易內依 FIFO 遞補至滿額。
資料：Session、Participant、Enrollment。Enrollment 以 participantId + sessionId 唯一。狀態 confirmed、waitlisted、cancelled；v1 無審核。所有狀態判斷在伺服器，前端只顯示回傳的結果。
報名：尚有名額就正取，滿額就候補；候補使用伺服器單調遞增序號 FIFO，不依客戶端時間或不穩定排序。重複報名回傳原有有效報名，不產生第二筆。取消後重新報名沿用唯一紀錄，重新排在當時隊尾，不能恢復舊順位。
取消：正取取消時，在同一交易內遞補當時第一位候補。重複取消必須冪等，不得再次遞補。候補取消不影響其他人的正取。關閉報名後禁止新報名，仍允許已報名者取消並依規則遞補。
併發：最後一個名額同時被多位學員請求時，不得超收；同一人同時送兩次請求也只能有一筆。資料庫約束與交易必須支撐規則。
交付：React TypeScript / Vite、Express、SQLite；乾淨的共用 starter 與同一 dependency lockfile。3 場次、6 身分，其中一場容量 3；固定種子與一鍵重設，前後端可啟動，測試命令可重現，README 記錄步驟與限制。
非目標：金流、Email、真實 SSO、手機原生 App、雲端部署、正式個資處理。
v1 範圍確認後，訪談結論存為共同 PRD。
