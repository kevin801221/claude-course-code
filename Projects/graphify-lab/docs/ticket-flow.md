# 工單 v2：PM 確認的需求

本文件描述**希望得到的行為**。初版 starter 仍要求 email，不代表已達成本規格。
本練習的「儲存」是呼叫 save_ticket 並回傳工單 dict；通知只產生模擬結果，不寄信、不寫資料庫。

| 輸入 | 建立工單 | 通知 |
|---|---|---|
| 有標題，email 包含 `@` | 儲存一次 | 呼叫 send_notification 一次 |
| 有標題，email 為 None、空字串或只有空白 | 儲存一次，email 欄位是 None | 不呼叫 |
| 有標題，有填 email 但不含 `@` | 拒絕，不儲存 | 不呼叫 |
| 標題去除前後空白後是空的 | 拒絕，不儲存 | 不呼叫 |

email 的空白先去除。含 `@` 是課堂簡化規則；不宣稱檢查真實地址。保留入口 `submit_ticket(title, email)`，本題的「可選」指可傳入空值，不要求移除第二個參數。
