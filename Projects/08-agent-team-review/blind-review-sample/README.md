# 盲評一致性 sample — agent team 不可替代性的演練標的

> 三份「同一個產品 MeetNote 的 landing page 主文案」，故意做到**沒有客觀最優**：
> 各自在不同維度強、不同維度弱。用來證明單一 agent 連評的**順序污染**，
> 以及 agent team 獨立盲評為什麼是架構上唯一的解。

## 三份文案的設計（講師對答案用）

| 文案 | 強 | 弱 |
|---|---|---|
| [copy_a.md](copy_a.md) | 文筆最順、情緒鋪陳完整、結尾有記憶點 | 「怎麼做到的」說得模糊，信任建立空 |
| [copy_b.md](copy_b.md) | 訴求最準、賣點完整、有實證數據、信任閉環 | 資訊密度高、段落長，缺一句難忘的話 |
| [copy_c.md](copy_c.md) | 最短、節奏最快、記憶點最強、掃讀體驗最好 | 完全沒講機制/平台/憑證，冷流量信任資訊全缺 |

**關鍵：A 和 C 品質「真的接近」**——這是順序污染能蓋過真實品質差距的前提。
B 客觀稍強（唯一做到信任閉環），所以它扛得住順序雜訊。

## 已驗證的真實打臉數據

用同一個強模型、同一份評分 prompt，只改**閱讀順序**，跑兩次：

| 文案 | 順序 A→B→C 得分 / 名次 | 順序 C→B→A 得分 / 名次 |
|---|---|---|
| A | 84　🥈 第 2 | **86　🥉 第 3** |
| B | 88　🥇 第 1 | 88　🥇 第 1 |
| C | 82　🥉 第 3 | **84　🥈 第 2** |

讀法：
- **A 和 C 的名次互換了**——只因為閱讀順序不同，跟文案品質無關。
- **B 穩居第 1**——它客觀夠強，扛得住雜訊。
- 結論：**單一評審的排名，在「接近的候選之間」被順序污染。換更強的模型不會解決——這兩次用的就是同一個強模型。**

## 怎麼跑這個演練

完整教案見 [`../../../docs/walkthroughs/agent_team_walkthrough.md`](../../../docs/walkthroughs/agent_team_walkthrough.md)。

兩組對照：

1. **單一 agent 組**（對照組）：一個 agent 連評三份出排名 → 把檔案順序對調再跑一次 → 名次漂移，當場打臉
2. **agent team 組**：3 個隊友各自獨立評全部三份，**互不通氣、主管不准先看單一評語**，最後主管只比對三份獨立評分，標出「分歧最大的那份 = 它本身最有爭議」

## 為什麼故意選「文案」這種高主觀標的

文案主觀性高 → 接近的候選之間，順序雜訊的影響**肉眼可見**，教學「哇」點最強。
真實工程場景（評 3 份 PR、3 個架構方案）原理完全一樣，只是污染幅度小一點、
要更仔細看才察覺。walkthrough 裡有「換成工程標的」的遷移 prompt。
