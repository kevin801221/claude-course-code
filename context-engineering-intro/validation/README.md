# 終極驗證命令 (Ultimate Validation Command)

**使用一個命令即可分析您的程式碼庫並生成全面的驗證工作流。**

## 快速開始

### 1. 生成您的驗證命令
```bash
/ultimate_validate_command
```

這會分析您的程式碼庫並建立為您的專案量身定制的 `.claude/commands/validate.md`。

### 2. 執行完整驗證
```bash
/validate
```

這會執行所有驗證：Lint 檢查、型別檢查、風格檢查、單元測試以及全面的端到端 (E2E) 測試。

## 它的作用

### 分析您的程式碼庫
- 偵測您已有的驗證工具 (ESLint, ruff, mypy, prettier 等)。
- 尋找您的測試設定 (pytest, jest, Playwright 等)。
- 理解您的應用程式架構 (路由、端點、資料庫綱要)。
- 檢查現有的測試模式和 CI/CD 配置。

### 生成 validate.md
建立一個包含以下階段的驗證命令：

1. **Lint 檢查** —— 使用您配置的 Linter。
2. **型別檢查** —— 使用您配置的型別檢查器。
3. **風格檢查** —— 使用您配置的格式化工具。
4. **單元測試** —— 執行您現有的單元測試。
5. **端到端 (E2E) 測試** —— **這是關鍵部分**。

## E2E 測試的神奇之處

生成的 E2E 測試旨在實現**極其全面**的效果，以至於您無需手動測試。

### 針對前端應用程式
使用 Playwright：
- 測試每個使用者流程 (註冊、登入、CRUD 操作)。
- 與表單、按鈕、導覽進行互動。
- 驗證資料持久性和 UI 更新。
- 測試錯誤狀態和驗證。
- 涵蓋所有路由和功能。

### 針對後端應用程式
使用 Docker 和自訂腳本：
- 在容器中啟動完整的技術疊。
- 使用真實請求測試所有 API 端點。
- 直接與資料庫互動以驗證數據。
- 測試完整的工作流 (身分驗證 → 資料操作 → 驗證)。
- 如果需要，建立測試工具或 API 端點。

### 針對全端應用程式
- 測試從 UI 到 API 再到資料庫的完整流程。
- 驗證所有層級的資料一致性。
- 端到端模擬真實使用者的行為。

## 核心理念

**如果 `/validate` 通過，您的應用程式就能正常運作。**

生成的 E2E 測試具有足夠的創造力和徹底性，使得手動測試變得不再必要。它完全按照真實使用者與應用程式互動的方式進行測試。

## 範例

對於一個 React + FastAPI 應用程式，生成的命令可能會：

1. 執行 ESLint、TypeScript 檢查、Prettier。
2. 執行 pytest 和 Jest。
3. **E2E 測試：**
   - 使用 Playwright 測試「使用者註冊 → 登入 → 建立項目 → 編輯 → 刪除」。
   - 啟動後端 Docker 容器。
   - 使用 curl 測試所有 API 端點。
   - 直接查詢資料庫以驗證資料完整性。
   - 測試錯誤處理、權限、驗證。

**結果：** 完全確信一切正常。

## 有何不同

傳統測試：
- ❌ 隔離的單元測試
- ❌ 手動 E2E 測試
- ❌ 覆蓋範圍存在缺口
- ❌ 耗時

此方法：
- ✅ 全部自動化
- ✅ 像真實使用者一樣測試
- ✅ 全面的 E2E 覆蓋
- ✅ 一個命令驗證所有內容

## 開始使用

執行 `/ultimate_validate_command` 來生成您的驗證工作流，然後在您需要對程式碼有完全信心時使用 `/validate`。

生成的命令會適應您的程式碼庫並進行徹底測試。
